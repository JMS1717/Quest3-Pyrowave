# Experiment 5 — Fused Haar viability on real worn XR content

## 1. Executive result

Accepted clips: 14 across 1 classes. Live fused-Haar engineering gate: **UNKNOWN** (A_gameplay not measured). Per-class gates are in section 12; nothing here is an average across classes.

Supplemental (not one of the eight preregistered classes): X_other = 14 clips of SteamVR Home worn with unscripted, mostly static head motion. Haar matched-PSNR-Y overhead: median of clip medians +19.0 %, largest clip p90 +35.2 %, worst frame +35.3 % (band PASS if it were a gated class). Three view-dependent groups appear (about +11 %, +26-28 %, +35 %), so the spread across views inside one scene is wider than the spread across frames inside one clip.

## 2. Exact hypotheses

H5: on representative worn XR content, fused Haar reaches comparable perceptual quality to CDF 9/7 with a bitrate penalty small enough that its ~48.6 % reconstruction-time reduction (Experiment 4, standalone, matched clocks) is a favourable latency/bandwidth trade. Falsified for a general replacement if representative content consistently needs > 50 % more bytes at matched PSNR-Y or shows substantial perceptual/temporal failures the global metric hides; partially supported if only some classes pass. Gate metric: matched-PSNR-Y bitrate overhead, bands frozen (<= 15 STRONG PASS, <= 25 PASS, <= 50 CONDITIONAL, > 50 FAIL, else UNKNOWN).

## 3. Experimental environment

Galaxy XR (Adreno 740) client at the candidate operating point (60 % render, 400 Mbps PyroWave UDP, 90 Hz, gaze centre 0.20, compute path); RTX 3090 PC encoder; clips are the encoder's own input planes (1984x896 side-by-side foveated, BT.709 full-range 4:4:4) written losslessly through the runtime trigger (`ALVR_PYROWAVE_DUMP_TRIGGER`), 90 consecutive frames with a per-frame timestamp sidecar. Offline scoring: PyroWave PC encoder/decoder at the frame's native size, ffmpeg psnr/ssim/libvmaf (PSNR-HVS, VMAF). Corpus and index frozen before analysis (hash in `index.frozen-*.sha256`). The index's `path` column was later redacted (the local folder became `<workspace>`), so the published file hashes to `b6a9d148dc0efbc094eefd788ef2f0f0e4ffd9a60df16b2f5c462caeee8d8142`; the recorded hash is of the file as frozen, whose rows are otherwise identical.
